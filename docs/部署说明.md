# 静态文件部署

Mac 构建，GitHub 的 main 分支保存源码，site 分支只保存生成的网页。服务器只需要 Git 和 Nginx，不需要 Node.js、npm、Docker 或 GitHub 登录。

## Mac 发布

需要 Node.js 22.12 或以上。修改完成后先提交、推送 main，再发布：

```bash
npm ci
git add .
git commit -m "Update website"
git push origin main
npm run publish:site
```

如果没有源码修改，不需要重复提交。publish:site 会构建网页、核对备案号与资源、检查 main 已推送，再把静态文件推送到 site。不会切换本地源码分支，不会强制覆盖远程更新。源码未提交或未推送时会停止。

## 服务器首次部署

原来的 /opt/vergil 是源码目录，可以保留。新的静态目录为 /var/www/vergil，不要覆盖已有非空目录。

```bash
git clone --branch site --single-branch https://github.com/Vergil-coder/vergil-site.git /var/www/vergil
```

在修改配置前，先检查 Nginx 是否已有 vergil.me：

```bash
nginx -T 2>&1 | grep -E '^# configuration file|^[[:space:]]*(server_name|root)[[:space:]]'
```

main 分支的 deploy/vergil.me.conf 是 HTTP 示例，deploy/vergil.me.https.conf 是 HTTPS 示例，root 均为 /var/www/vergil。只修改个人站配置；已有域名配置时先备份并编辑原配置，避免重复新增。Pactime、Mellowfin 和公司站点无需修改。

若使用服务器现有源码目录中的示例，先更新源码，以免误用旧路径：

```bash
git -C /opt/vergil pull --ff-only
```

确认没有重复 vergil.me 配置后，将 HTTP 示例放到 /etc/nginx/conf.d/vergil.me.conf。修改后执行：

```bash
nginx -t && systemctl reload nginx
curl --resolve vergil.me:80:127.0.0.1 http://vergil.me/connection-check.txt
```

HTTPS 示例要求 /etc/letsencrypt/live/vergil.me 下已有根域名证书，不能复用仅含 App 子域名的证书。证书不存在时先提供 HTTP，另行申请根域名证书。

Nginx 必须禁止访问隐藏目录，示例中的 location ~ /\. { deny all; } 会阻止读取静态目录里的 .git。网站首次上线后核对这一规则。

## 以后更新

Mac 完成发布后，服务器只执行：

```bash
git -C /var/www/vergil pull --ff-only
```

无需重新构建或 reload Nginx。有服务器本地文件修改时先核对，不使用 reset --hard 强制覆盖。

## DNS 和备案

vergil.me 的 @ A 记录应指向实际部署服务器的公网 IP。上线后从外网打开网站，核对页脚「粤ICP备2024281609号-2」及工信部链接，再提交备案订单。
